# 병합에 강한 노드 트리

상태: 구현 완료 · 날짜: 2026-10-24

> [0.0.3 요구사항](../requirements/0.0.3.md) R16 을 받아 쓴다. 요구사항이 "무엇" 을 정했고,
> 이 문서는 "어떻게" 와 "왜 그렇게" 를 적는다. 구현은 이 문서 뒤에 온다.

## 1. 원칙 — 공유 상태를 없앤다

충돌은 두 브랜치가 **같은 바이트**를 고칠 때 난다. 그러니 묻는 것은 하나다 — 서로 다른 노드를
고치는 두 작업이 공유하는 바이트가 있는가.

| 지금 공유하는 것 | 누가 고치나 | 이 설계에서 |
| --- | --- | --- |
| 부모의 `children` 목록 | 형제를 더하고 빼고 옮기는 모든 작업 | 없앤다. 디렉터리가 인덱스다 (§2) |
| 형제의 순번 | 끼우는 자리 뒤의 모든 형제 | 분수 색인 — 끼운 노드만 값을 얻는다 (§3) |
| 루트 `node.md` 전체 | 노드 디렉터리 문서에 `apply` 하는 모든 작업 | 바뀐 노드 파일만 쓴다 (§4) |
| `.dockit/store` | 모든 인덱싱 | 이미 `.gitignore` 에 있다. 파생물이다 |

공유 상태를 없앨 수 없는 것 — 같은 노드를 두 브랜치가 고친 경우 — 은 진짜 충돌이므로 Git 이
알리는 것이 맞다. 텍스트는 깨끗한데 뜻이 깨지는 것은 §5 가 다룬다.

## 2. 디렉터리가 인덱스다

```
principle/불변식은-생성자에서-검증한다/
  node.md               ← children 이 없다
  norm/node.md
  rationale/node.md
  rationale/더-좁은-경우/node.md
  example/node.md
```

조립기(`nodes/reader.ts`)는 디렉터리를 열어 `node.md` 를 가진 하위 디렉터리를 모두 읽고,
§3 의 순서로 정렬해 끼운다. `node.md` 가 없는 하위 디렉터리는 노드가 아니다 — 병합에서 한쪽이
노드를 지우고 다른 쪽이 그 디렉터리에 파일을 더했을 때 남는 껍데기다. 건너뛰고 NODE003 으로
알린다 (R16.8). 점으로 시작하는 디렉터리는 지금처럼 보지 않는다 (`readEntries`).

이름의 검사(NODE005)는 그대로 한다. 인덱스에 적힌 값이 아니라 디렉터리 이름이 대상이 될 뿐이다.
NODE006(같은 이름 두 번)은 파일 시스템이 막으므로 새 형태에서는 나지 않는다.

### 2.1 옛 형태

루트든 하위 노드든 frontmatter 에 `children` 이 있으면 **그 노드의 자식은** 예전 규칙으로 읽는다 —
인덱스 순서, NODE002 · NODE003(인덱스에 없는 디렉터리) · NODE006 그대로. 그리고 NODE007 경고를
낸다. 노드마다 따로 판단하므로 반쯤 옮긴 트리도 읽힌다.

`split` 은 언제나 새 형태로 쓴다. 노드 디렉터리 문서에 `split --document` 를 다시 돌리면 그 자리에
인덱스 없는 파일들이 쓰인다 — 이것이 옮기는 길이다.

## 3. 순서

형제의 정렬 열쇠는 세 겹이다.

```ts
rank   = strict 타입이고 규약이 이 자리에 선언한 섹션이면 선언 순번, 아니면 ∞
order  = 자기 node.md 의 `order` (없으면 '')
name   = 디렉터리 이름
sort by (rank, order, name)
```

규약의 자리는 키 경로로 찾는다 — 문서 바로 아래는 `sectionsOf(type)`, 그 아래는
`sectionAt(type, keyPath).sections`. 규약이 선언하지 않은 섹션은 SCH001 이 오류로 알리지만, 읽기는
멈추지 않아야 하므로 ∞ 로 맨 뒤에 둔다.

### 3.1 분수 색인

`order` 의 값은 `0-9a-z` 36 진 자릿수의 문자열이고, 사전순이 곧 순서다. `between(a, b)` 는
`a < c < b` 인 가장 짧은 `c` 를 낸다 (`a = ''` 는 맨 앞, `b = null` 은 맨 뒤).

```
between('', null)  = 'i'
between('i', null) = 'r'
between('i', 'r')  = 'n'
between('i', 'j')  = 'ii'
```

`0` 으로 끝나는 값을 만들지 않는다. `'a0'` 과 `'a'` 사이에는 아무것도 없기 때문이다. 읽을 때도
그런 값은 PRS 진단으로 거절한다 — 손으로 적은 값이 끼울 자리를 막지 않게 한다.

### 3.2 쓸 때 — 적지 않을 수 있으면 적지 않는다 (R16.5)

`splitDocument` 는 부모마다 자식을 rank 로 무리 짓는다.

1. **rank 가 줄어드는 자리가 있으면** 그 순서는 이 형태로 표현할 수 없다. strict 타입에서 SCH003
   이 이미 오류인 문서다. 정보를 잃지 않도록 그 부모에만 옛 `children` 인덱스를 쓴다 — 읽을 때
   NODE007 이 함께 나므로 조용히 남지 않는다
2. 무리 안의 이름 순서가 문서 순서와 같고, 앞서 적힌 `order` 가 하나도 없으면 아무것도 적지 않는다
3. 아니면 무리의 모두가 `order` 를 갖는다. 앞서 적힌 값 중 **문서 순서대로 증가하는 가장 긴
   부분수열**은 그대로 두고, 나머지 자리만 이웃 사이에서 `between` 으로 새로 만든다

"앞서 적힌 값" 은 호출자가 준다 (`previousOrder(directory)`). `apply` 는 디스크의 노드 파일에서 읽고,
처음 흩는 `split` 은 아무것도 주지 않는다. 3 의 가장 긴 부분수열이 R16.3 의 "다른 형제의 값을
바꾸지 않는다" 를 지킨다 — 하나를 끼우면 그 하나만 새 값을 얻는다.

## 4. `apply` 가 노드 파일로 되쓴다

```ts
// nodes/update.ts
export function planNodeWrites(
  before: Document, after: Document, schema: Schema, files: NodeFiles,
): { write: NodeFile[]; remove: string[] }
```

1. `files` 에서 앞서 적힌 `order` 를 읽는 `previousOrder` 를 만든다
2. `before` 와 `after` 를 같은 `previousOrder` 로 각각 흩는다
3. 같은 경로의 결과가 같으면 쓰지 않는다 — 디스크의 바이트를 그대로 둔다
4. 다르거나 새로 생긴 경로는 쓴다
5. `before` 에만 있는 경로는 지운다

3 이 핵심이다. 흩은 결과를 디스크와 비교하지 않고 **고치기 전 문서를 흩은 결과**와 비교한다.
그래서 작성자가 frontmatter 키 순서를 달리 적었거나 줄바꿈을 다르게 두었어도, 뜻이 바뀌지 않은
노드는 손대지 않는다 (R16.6). 디스크와 비교하면 처음 `apply` 하는 순간 모든 파일이 정규화되며
바뀐다.

계획은 순수 함수이고, 파일을 쓰고 지우는 것은 CLI 가 한다. 지운 뒤 비게 된 디렉터리는 안쪽부터
지운다. 노드 파일이 아닌 파일은 건드리지 않는다.

한 파일 문서는 지금처럼 `serializeDocument` 로 한 파일에 쓴다.

## 5. 텍스트는 깨끗한데 뜻이 깨지는 것

| 병합 결과 | 진단 | 상태 |
| --- | --- | --- |
| 사라진 노드를 가리키는 링크 | REF002 | 있음 |
| 위치 주소 링크 — 다른 노드를 가리킬 수 있다 | REF006 | **새로** |
| 한 문서 안의 안정 식별자 중복 | AUX004 | 있음 |
| 문서 식별자 중복 | REF005 | 있음 |
| `node.md` 없는 노드 디렉터리 | NODE003 | 뜻을 바꿈 (§2) |
| 같은 `order` | — | 이름이 가른다. 진단 거리가 아니다 (R16.4) |

REF006 은 `workspace/graph.ts` 의 관계 검사에 더한다. 대상의 조각이 위치 주소(`path`)이면 오류다.
문서 자신을 가리키는 빈 조각은 문서 주소이므로 괜찮다. `relation.link` 의 CMD016 은 같은 문서에만
걸던 조건을 모든 대상으로 넓힌다.

병합의 관문은 `dockit check --strict` 하나다. README 에 CI 에서 병합 뒤 돌리라고 적는다. 훅이나
드라이버를 설치하게 하지 않는다 (0.0.3 §5 Q1).

### 6.1 증분 캐시

문서의 캐시 열쇠는 이미 디렉터리를 걸어 모은 노드 파일들의 지문이라 (`filesOf`), 부모를 고치지
않고 노드를 더해도 열쇠가 바뀐다. 다만 `node.md` 가 없는 디렉터리는 파일이 없어 지문에 들지
않으므로, 그런 디렉터리를 껍데기로 따로 세어 열쇠에 넣는다 — 넣지 않으면 NODE003 이 캐시에
가려진다. 껍데기가 없는 문서의 열쇠는 전과 같으므로 기존 캐시는 그대로 맞는다.

## 7. 층

새 파일은 `nodes/order.ts`(분수 색인과 정렬 열쇠)와 `nodes/update.ts`(쓰기 계획) 둘이다. 둘 다
`nodes/` 안에서 끝나고 저장소를 모른다. 층의 울타리(`layering.test.ts`)는 바뀌지 않는다.
