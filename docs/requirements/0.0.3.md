# 0.0.3 요구사항

상태: 초안 · 날짜: 2026-10-24

0.0.2 처럼 **구현보다 먼저** 무엇이 되어야 하는가를 정한다. 설계는 [0005](../design/0005-병합에-강한-노드-트리.md) 에 있다.

[0.0.1](0.0.1.md) 과 [0.0.2](0.0.2.md) 의 요구사항은 그대로 유지한다. 여기에는 **더하거나 바꾸는 것만** 적는다.

---

## 1. 범위

### 1.1 문제

문서의 원본은 Git 이 관리하는 마크다운이고, 여럿이 여러 브랜치에서 동시에 고친다. 지금의 저장
형태는 그 쓰임에 두 가지로 약하다.

**텍스트 충돌이 구조에서 나온다.** 부모 `node.md` 의 `children` 인덱스는 형제 전부가 공유하는
목록 하나다. 두 브랜치가 같은 부모 아래에 노드를 하나씩 더하면, 서로 다른 노드인데도 같은 줄
근처를 고치므로 Git 이 충돌을 낸다. 충돌을 손으로 풀다 한쪽을 빠뜨리면 디렉터리는 있는데
인덱스에 없는 노드(NODE003)나, 인덱스에는 있는데 디렉터리가 없는 노드(NODE002)가 남는다.

**충돌 없이 뜻이 깨진다.** Git 은 줄만 본다. 텍스트로 깨끗하게 합쳐져도 문서 사이의 약속이 깨질
수 있다.

| 한쪽 브랜치 | 다른 쪽 브랜치 | 합친 결과 |
| --- | --- | --- |
| 안정 식별자 `core` 를 지운다 | `…#core` 로 관계를 건다 | 가리키는 곳이 없는 링크 |
| `#norm` 앞에 블록을 끼운다 | `…#norm/2` 로 관계를 건다 | **다른 블록**을 가리키는 링크 — 오류도 나지 않는다 |
| 같은 문서에 `id=limit` 블록을 더한다 | 같은 문서에 `id=limit` 블록을 더한다 | 한 주소가 두 노드 |

**도구 자신이 범위를 넓힌다.** 노드 디렉터리 문서에 `apply` 를 돌리면 문서 전체를 한 파일 형식으로
루트 `node.md` 에 써 버린다. 하위 노드 디렉터리는 인덱스에서 떨어져 고아가 되고(NODE003), 블록
하나를 고친 일이 문서 전체를 고친 것처럼 보인다 — 다른 브랜치의 어떤 고침과도 충돌한다.

### 1.2 하는 것

- 노드를 더하고 빼고 고치는 일이 **그 노드의 파일만** 건드리게 한다 (R16.1~R16.5)
- `apply` 가 노드 디렉터리 문서를 노드 파일들로 되쓰고, 뜻이 바뀐 파일만 쓰게 한다 (R16.6)
- 다른 브랜치의 편집에 살아남지 못하는 주소를 관계에 쓰지 못하게 한다 (R16.9)
- 텍스트 병합이 놓치는 뜻의 깨짐을 `check` 하나가 모두 잡게 한다 (R16.10)

### 1.3 하지 않는 것 (비목표)

| 비목표 | 근거 |
| --- | --- |
| Git 병합 드라이버 (`.gitattributes` `merge=dockit`) | 클론마다 설치해야 하고, 호스팅 서비스의 웹 병합에서는 돌지 않는다. 충돌을 푸는 도구보다 충돌이 나지 않는 형태가 낫다 (§5 Q1) |
| 같은 노드를 두 브랜치가 고친 충돌의 자동 해소 | 그것은 진짜 충돌이다. 사람이 골라야 한다 |
| 한 파일 문서의 충돌 줄이기 | 여럿이 고치는 문서는 `split` 으로 흩으면 된다. 한 파일은 한 사람이 쓰는 형태다 |
| 안정 식별자 이름 바꾸기와 링크 따라 고치기 (rename refactor) | 깨진 링크는 R16.10 이 잡는다. 따라 고치는 일은 별도 명령이다 |
| 문서 사이 노드 옮기기 | 0.0.1 과 같다 |

## 2. 병합 안전 (R16)

| ID | 요구사항 | 강제 |
| --- | --- | --- |
| R16.1 | 노드 파일은 하위 노드 목록을 갖지 않는다. 하위 노드는 `node.md` 를 가진 하위 디렉터리이고, 디렉터리가 곧 인덱스다 | 테스트 |
| R16.2 | 형제 순서는 결정적이다 — ① 순서가 `strict` 인 타입에서 규약이 선언한 순서 ② 자기 `node.md` 의 `order` ③ 디렉터리 이름. 앞 기준이 같을 때만 다음 기준을 본다 | 테스트 |
| R16.3 | `order` 는 분수 색인 문자열이다 (`[0-9a-z]+`, `0` 으로 끝나지 않는다). 두 형제 사이에 끼울 때 **다른 형제의 값을 바꾸지 않는다** | 테스트 |
| R16.4 | 같은 `order` 는 이름으로 가른다. 두 브랜치가 같은 자리에 끼워도 합친 결과가 하나로 정해진다 | 테스트 |
| R16.5 | 규약 순서와 이름 순서로 표현되는 자리에는 `order` 를 적지 않는다. 이미 적힌 값은 순서가 맞는 한 다시 쓰지 않는다 | 테스트 |
| R16.6 | `apply` 는 노드 디렉터리 문서를 노드 파일들로 되쓴다. 뜻이 바뀐 노드 파일만 쓰고, 사라진 노드의 파일은 지운다. 손대지 않은 노드 파일은 바이트 단위로 그대로다 | 테스트 |
| R16.7 | `children` 인덱스가 남은 노드 파일은 예전처럼 읽되 `NODE007` 로 알린다. `split` 이 인덱스 없는 형태로 다시 쓴다 | 테스트 |
| R16.8 | `node.md` 가 없는 하위 디렉터리는 노드가 아니다. 건너뛰고 `NODE003` 으로 알린다 | 테스트 |
| R16.9 | 관계 대상은 문서이거나 안정 주소다. 위치 주소(`#norm/2`)는 `relation.link` 가 거절하고(`CMD016`) 검사기가 오류로 알린다(`REF006`) | 테스트 |
| R16.10 | 서로 다른 노드를 고친 두 브랜치는 Git 이 충돌 없이 합친다. 합친 뒤 뜻이 깨진 경우(`REF002` `REF006` `AUX004` `REF005` `NODE003`)는 `check` 가 모두 잡는다 | 테스트 |

R16.1 이 이 문서의 존재 이유다. 부모가 자식 목록을 들고 있는 한, 형제를 더하는 모든 브랜치가
부모 파일 하나를 함께 고친다. 목록을 디렉터리로 옮기면 Git 의 tree 가 인덱스 노릇을 하고, 서로
다른 노드를 더한 두 브랜치는 서로 다른 파일만 만든다. 0.0.1 의 "부모는 자식을 소유하지 않는다" 는
그대로다 — 부모는 이제 이름조차 들고 있지 않고, 조립기가 디렉터리에서 찾는다. Git 의 tree 가
작업 트리에서 계산되는 것과 같다.

R16.2 에서 규약이 먼저인 까닭: 내장 프리셋은 모두 `order: strict` 이고, 거기서 형제 순서는
SCH003 이 이미 강제한다. 강제되는 순서를 파일에 다시 적으면 정보 없이 충돌 면적만 는다.
"규약이 아는 제목은 적지 않는다" · "규약이 정한 기본 역할은 적지 않는다" 와 같은 원칙이다.
`order` 가 실제로 필요한 곳은 `order: any` 타입과 규약이 선언하지 않은 하위 섹션뿐이다.

R16.3 · R16.4 는 R16.1 을 순서가 자유로운 곳까지 넓힌다. 정수 순번이면 하나를 끼울 때 뒤 형제를
모두 다시 매겨야 하고, 그것이 다시 공유 상태가 된다. 분수 색인은 끼운 노드 하나만 값을 얻는다.
두 브랜치가 같은 두 형제 사이에 끼우면 같은 값을 얻을 수 있는데, 이름이 갈라 주므로 충돌도
모호함도 없다 — 순서가 작성자 기대와 다를 수는 있지만 결정적이고, 고치는 것은 `order` 한 줄이다.

R16.6 은 버그 수정이기도 하다 (§1.1). "고친 블록만 새로 쓰인다" (0.0.1 R5) 를 파일 단위로 지킨다.

R16.9 는 0.0.1 의 CMD016 을 넓힌다. 0.0.1 은 같은 문서 안의 링크만 안정 주소를 요구했다. 위치 주소는
다른 문서의 편집에도 똑같이 무너지고, 무너져도 오류가 나지 않는다 — 다른 노드를 가리킬 뿐이다.

R16.10 의 다섯 진단은 이미 있거나(REF002 · AUX004 · REF005 · NODE003) 이번에 생긴다(REF006).
새로 할 일은 그것을 병합의 관문으로 쓰라고 말하는 것과, 그것이 실제로 잡는다는 것을 Git 으로
합쳐 보는 테스트다.

## 4. 인수 조건

0.0.2 §4 의 넷이 그대로 통과하고, 더해서:

- R16 의 테스트가 모두 통과한다
- `rules/` 의 노드 파일에 `children` 이 남아 있지 않고, `npm run check` 가 진단 없이 끝난다
- `rules/` 를 옮기기 전과 뒤의 스냅샷을 `diff` 하면 결과가 비어 있다 — 형태만 바뀌고 문서는 그대로다

## 5. 정한 것

| | 질문 | 정한 것 | 고르지 않은 것 | 까닭 |
| --- | --- | --- | --- | --- |
| Q1 | 충돌을 어디서 없앨까 | 저장 형태에서 (R16.1) | 인덱스를 두고 병합 드라이버로 푼다 | 드라이버는 클론마다 설치해야 하고 웹 병합에서 돌지 않는다. 형태가 충돌을 만들지 않으면 아무것도 설치하지 않아도 된다 |
| Q2 | 순서를 어디에 적을까 | 규약 → 자식의 `order` → 이름 (R16.2) | 모든 자식에 `order` | 내장 프리셋은 전부 `strict` 라 대부분의 문서에서 `order` 가 한 줄도 필요 없다 |
| Q3 | 순번의 형태 | 분수 색인 문자열 (R16.3) | 정수 · 10 간격 정수 | 정수는 끼울 때 형제를 다시 매긴다. 10 간격은 몇 번 끼우면 결국 다시 매긴다 |
| Q4 | 옛 `children` | 읽고 알린다 (R16.7) | 바로 오류 · 조용히 읽기 | 깨지는 저장소가 없고, 옮길 길(`split`)이 있다. `rk:` → PRS006 과 같은 길이다 |
| Q5 | 위치 주소 관계의 심각도 | 오류 (R16.9) | 경고 | 틀린 노드를 가리키는 링크는 없는 링크보다 나쁘다 — 없는 링크는 적어도 REF002 가 난다 |
