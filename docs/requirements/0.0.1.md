# 0.0.1 요구사항

상태: 충족 · 날짜: 2026-10-15

이 문서는 **지금 구현된 것을 0.0.1 의 요구사항으로 정의한다.** 설계 근거가 아니라
"무엇이 되어야 하는가" 와 "무엇으로 그것을 확인하는가" 만 적는다 —
왜 그렇게 정했는지는 [설계문서](../design/) 에 있다.

요구사항마다 **강제 수단**이 있다. 수단이 "—" 인 것은 요구사항이 아니라 설명이다.

| 강제 | 뜻 |
| --- | --- |
| 타입 | 타입 시스템이 막는다. 검사기를 두지 않는다 |
| 오류 | 진단 코드로 차단한다. `check` 가 종료 코드 1 을 낸다 |
| 경고 | 진단 코드로 알린다. `--strict` 에서만 실패한다 |
| 테스트 | 테스트가 깨진다 |

---

## 1. 범위

### 1.1 하는 것

마크다운 문서를 블록 단위 트리로 구조화하고, 내용 주소로 인덱싱해 조각 단위로
질의·검증·조작한다. 1차 소비자는 AI 에이전트와 문서를 읽는 사람이다.

### 1.2 하지 않는 것 (비목표)

0.0.1 에서 명시적으로 제외한다. 없어서 못 한 것과 구분하기 위해 적는다.

| 비목표 | 근거 |
| --- | --- |
| 린터 연동 | 0001 §2 |
| 자동 수정 (autofix) | 0001 §2 |
| 웹 에디터 UI | 0001 §2 |
| 팩파일·델타 체인 | 0002 §7 — 필요해질 조건 세 가지를 적어 두었다 |
| 스냅샷 간 `diff` | 0003 §8 |
| 거둔 이력의 기록 | 0003 §2.2 — 남기지 않기로 **정했다** |
| 중간 보존 정책 (최근 n 개) | 0003 §2.1 — 정책은 둘뿐이다 |

## 7. 규약 적합성과 구조 상한 (R6)

| ID | 요구사항 | 강제 |
| --- | --- | --- |
| R6.1 | 섹션 구성·순서·중복·역할은 규약을 벗어날 수 없다 | 오류 `SCH001`~`SCH009` |
| R6.2 | 규범 진술의 문장 수 상한 (역할마다 선언) | 경고 `STR001` |
| R6.3 | 섹션이 담는 블록 수 상한 (섹션마다 선언) | 오류 `STR002` |
| R6.4 | 트리 깊이 상한 (타입마다 선언, 기본 3 · 문서를 1 로 센다) | 오류 `STR003` |
| R6.5 | 형제 수 상한 (전역 기본 9) | 경고 `STR004` |
| R6.6 | 문서 전체 블록 수 상한 (전역 기본 60) | 경고 `STR005` |
| R6.7 | 참조는 존재하고, 비순환 관계는 순환하지 않아야 한다 | 오류 `REF002`·`REF003` |
| R6.8 | 짝이 맞아야 하는 관계는 양쪽에 걸려야 한다 | 경고 `REF004` |
| R6.9 | 같은 진술이 두 곳에 있으면 알린다. 링크로 잇는 편이 낫다 | 경고 `REF001` |

상한은 전부 규약에서 바꿀 수 있다. 오류와 경고가 갈리는 기준은 **누가 상한을 선언했는가** 다.

| | 선언 위치 | 강제 |
| --- | --- | --- |
| R6.3 R6.4 | 규약이 섹션·타입마다 **직접 선언한** 상한 | 오류 |
| R6.2 R6.5 R6.6 | 역할 선언이 생략 가능하거나, 전역 기본값인 정량 기준 | 경고 |

규약이 "이 타입은 깊이 3 까지" 라고 적었다면 그것은 지켜야 하는 약속이고, 전역 기본값 9 는
눈금일 뿐이다. 구조 위반은 차단하고 눈금은 알린다 (0001 §2).

**타입으로 막을 수 있으면 검사기를 두지 않는다.** R2.2·R2.3 에 검사기가 없는 이유다.

## 10. 내용 주소 저장소 (R9)

| ID | 요구사항 | 강제 |
| --- | --- | --- |
| R9.1 | 블록이 blob, 노드가 tree, 작업공간이 snapshot 이다 | 테스트 |
| R9.2 | 주소는 `<타입> <길이>\0<내용>` 의 SHA-256 이고, 객체마다 zlib 로 압축한다 | 테스트 |
| R9.3 | 같은 내용은 같은 주소다. 이미 있는 주소에는 다시 쓰지 않는다 | 테스트 |
| R9.4 | tree 항목은 **주어진 순서를 지킨다**. 순서가 다르면 다른 주소다 | 테스트 |
| R9.5 | 메타데이터는 정규 JSON (키 재귀 정렬) 으로 적어, 선언 순서가 달라도 같은 주소가 된다 | 테스트 |
| R9.6 | 줄 번호·파일 경로·원문 조각은 주소에 들어가지 않는다 — 내용이 아니라 위치다 | 테스트 |
| R9.7 | 저장소는 프로젝트의 어떤 층도 import 하지 않는다. 바이트만 안다 | 테스트 |
| R9.8 | 저장소는 node 기본 모듈만 쓴다 | 테스트 |
| R9.9 | 저장소를 import 하는 파일은 열거된 셋뿐이고, 문서→객체 변환은 `workspace/encode.ts` 가 소유한다 | 테스트 |

R9.4 가 Git 과 다른 점이다. Git 은 tree 항목을 이름으로 정렬하지만, 여기서는 순서가 곧
문서 순서라서 정렬하면 뜻이 바뀐다. 고유 순서가 없는 컬렉션·문서 자리에서만 정렬한다.

## 12. 거두기와 보존 정책 (R11)

| ID | 요구사항 | 강제 |
| --- | --- | --- |
| R11.1 | **진단은 문서와 규약만의 함수다.** 저장소 상태가 결과를 바꾸어서는 안 된다 | 테스트 + 원칙 |
| R11.2 | 거두기는 진단·기록·뿌리 주소를 바꾸지 않는다 | 테스트 |
| R11.3 | 보존 정책은 초기화할 때 정하고 그 뒤로 바꾸지 않는다 | — |
| R11.4 | 정책은 `head` (기본) 와 `all` 둘뿐이다 | 타입 |
| R11.5 | `all` 이면 거두지 않는다. `--force` 로 뚫리지 않는다 | 테스트 |
| R11.6 | `head` 로 거두면 작업 트리가 쓰는 만큼만 남는다 | 테스트 |
| R11.7 | 거두기를 거듭해도 더 줄지 않는다 | 테스트 |
| R11.8 | `--dry-run` 은 계획만 세우고 지우지 않는다 | 테스트 |
| R11.9 | 보존 정책은 cwd 를 타고 새지 않는다. 루트와 그 부모까지만 본다 | 테스트 |
| R11.10 | 거둔 뒤 HEAD 의 끊긴 부모 링크는 고쳐 쓰지 않는다 | 테스트 |
| R11.11 | 저장 정책은 저작 규약(`schema.yaml`)과 다른 파일에 있다 | — |

R11.1 이 거두기를 **구조적으로** 안전하게 만든다. 지우는 일이 진단을 바꿀 수 없으므로
최악이 다음 실행 한 번 느려지는 것뿐이다. 이 요구사항은 `rules/` 에 자기 자신의 원칙으로도
적혀 있다 (`principle/진단은-저장소-상태에-의존하지-않는다`).

R11.9 는 규약 찾기와 탐색 순서가 다르다. 규약이 어긋나면 진단이 어긋날 뿐이지만
보존 정책은 파일을 지운다.

측정값 (문서 10 개 중 하나를 50 번 고침):

```
거두기 전   객체 429 · 파생 59 · 스냅샷 50
거둔 뒤     객체  37 · 파생 10 · 스냅샷  1
            (빈 저장소에 같은 트리를 담았을 때와 같은 수)
불변식      진단·기록·뿌리 주소 전부 동일
```

## 13. 층 구조 (R12)

| ID | 요구사항 | 강제 |
| --- | --- | --- |
| R12.1 | 의존은 한 방향으로만 흐른다 | 테스트 |
| R12.2 | 양쪽 끝(`model`·`store`)이 아무것도 import 하지 않는다 | 테스트 |
| R12.3 | `render` 와 `query` 는 인덱스 산출물만 읽는다. 마크다운을 다시 파싱하지 않는다 | — |

| 층 | 위치 | 책임 |
| --- | --- | --- |
| L0 객체 저장소 | `src/store/` | 내용 주소·압축·stat 캐시. 바이트만 안다 |
| L1 저작 규약 | `src/schema/` | 문서 타입·섹션·역할·어휘를 선언. 질의에만 답한다 |
| L2 문서 객체 모델 | `src/model/` | 트리와 보조데이터. 아무것도 import 하지 않는다 |
| L3 조작 프로토콜 | `src/api/` | JSON 명령 객체. 원본을 바꾸지 않는다 |

나머지가 이 위에 얹힌다 — `parse` `serialize` `nodes` `validate` `workspace` `query` `render` `cli`.
